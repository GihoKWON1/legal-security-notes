# legal-security-notes

보안 기술/사고를 법률 실무 관점에서 분석하고, 가능한 범위에서 방어적 실습(탐지·대응 코드, 패치 전후 비교 환경)을 남기는 저장소입니다.

**공격코드(Exploit/PoC)는 이 저장소에 포함하지 않습니다.** 실제 공격을 가능하게 하는 트리거 입력, 페이로드, 익스플로잇 체인 코드는 작성·보관·공개 대상에서 제외합니다. 여기 담긴 코드는 (1) 취약 여부를 점검하는 탐지 스크립트, (2) 패치 전/후 환경을 비교하기 위한 구성, (3) 분석·보고 문서로만 구성됩니다.

## 폴더 구조

```
legal-security-notes/
├── docs/                      # 사건·취약점별 분석 문서 (한글, 자연어)
│   └── <날짜>-<사건명>/
│       ├── 01-분석.md         # 메커니즘, 영향범위, 타임라인, 대응현황
│       ├── 02-참고자료.md     # 원문(영문) 출처 링크 모음 — 번역하지 않고 링크만 수록
│       └── 03-결과보고서.md   # 아래 tools/lab 실습 결과를 종합한 보고서
├── tools/                     # 방어/탐지용 스크립트 (실행 가능한 코드)
│   └── <사건명>-check/
└── lab/                       # 패치 전/후 비교 등 실습 환경 (Docker 등)
    └── <사건명>/
```

## 작업 원칙

1. 분석 문서는 한글로 작성하고, 영문 원문은 번역하지 않고 출처 링크만 남긴다.
2. 실습은 방어적 목적(탐지, 패치 버전 비교)에 한정하고, 동작하는 공격 코드는 만들지 않는다.
3. 사실관계는 반드시 출처를 표기하고, 기관/매체별로 수치가 다를 경우(예: CVSS 점수) 그 차이를 그대로 기록한다.
4. 보고서 작성 시점의 패치 현황·악용 여부는 시점을 명시한다(취약점 정보는 계속 갱신되므로).
